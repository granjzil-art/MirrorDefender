# MirrorDefender 美术资产配置接口检查

> 日期：2026-07-31
> 范围：地块、建筑、投射物、关卡元素、装饰物、敌人、UI 图片、建筑选项卡面。
> 性质：只读检查；未修改实现代码、场景或资源。

## 1. 结论

当前实现只完成了两类可实际使用的美术入口：

1. **建筑本体**：`BuildingLevelStats.visual_scene: PackedScene` 已被运行时实例化。
2. **部分 UI 图标**：建筑卡图、敌人/地块图标和若干 HUD 按钮图标已有 `Texture2D` 字段及消费路径。

其余主要问题：

- `TileDefinition.visual_scene` 和 `EnemyDefinition.visual_scene` **只有字段，没有运行时消费**。
- 建筑、敌人、复制体三类投射物均写死为程序化 `BoxMesh`，没有模型接口。
- “关卡机关投射物”和“装饰物”目前连数据模型、关卡序列化和运行时管理器都不存在。
- 关卡元素虽然声明 `visual_scene`，本体与复制体仍只生成程序化灰盒。
- 建筑卡目前只支持一张前景 `card_icon`，不支持完整卡面背景、框体、状态图等资产配置。
- UI 美术接口分散在各面板，很多面板或状态仍是场景内 StyleBox/硬编码颜色，没有统一 UI 美术配置资源。

## 3. 关键证据

### 3.1 地块与关卡元素

- 字段已声明：`scripts/tile/TileDefinition.gd:38-46`。
- 注释明确写成 Future art hook：`scripts/tile/TileDefinition.gd:45-46`。
- 运行时本体仍走批量几何：`scripts/tile/TileRenderer.gd:151-189`。
- 元素仍按枚举生成尖刺/空洞/岩石：`scripts/tile/TileRenderer.gd:247-330`。
- 复制体内容快照也重新生成 `ImmediateMesh`：`scripts/tile/TileRenderer.gd:110-142`。

因此，只给 `TileDefinition.visual_scene` 拖入场景目前不会产生任何运行时效果。

### 3.2 建筑

- 每级模型字段：`scripts/building/BuildingLevelStats.gd:36-39`。
- 实际实例化：`scripts/building/Building.gd:461-479`。
- 空值灰盒：`scripts/building/Building.gd:488-519`。
- 复制建筑通过源建筑当前视觉快照复用本体表现：`scripts/building/Building.gd:548-577`。

当前资源只有箭塔 1 级绑定正式场景：

- `resources/buildings/ArrowTower.tres:5`
- `resources/buildings/ArrowTower.tres:22-30`

箭塔 2、3 级及激光塔、屏障、边屏障均未配置 `visual_scene`，因此升级或使用其他建筑时仍回退灰盒。

额外漏洞：配置了非 `Node3D` 根场景时，`Building.gd:470-479` 会释放错误实例，但不会补建灰盒主体。

### 3.3 投射物

- 我方：`scripts/combat/Projectile.gd:68-80` 固定 `BoxMesh`。
- 敌方：`scripts/combat/EnemyProjectile.gd:100-112` 固定 `BoxMesh`。
- 复制体：`scripts/mirror/MirrorProjectionProjectile.gd:72-84` 固定 `BoxMesh`。
- 复制体当前只从源建筑读取速度、尺寸和颜色：`scripts/mirror/MirrorManager.gd:623-650`。

已有资产 `assets/projections/Arrow/arrow.tscn`，但当前没有任何现役脚本、资源或场景引用它。

### 3.4 敌人

- 模型字段已声明：`scripts/unit/EnemyDefinition.gd:35-40`。
- `EnemyUnit.configure_unit()` 只读取颜色和灰盒高度：`scripts/unit/EnemyUnit.gd:118-130`。
- `CombatTarget` 固定生成胶囊体：`scripts/combat/CombatTarget.gd:92-110`。

因此，给 `EnemyDefinition.visual_scene` 配置场景同样不会生效。正式模型接入时还需要定义受击点、血条高度、投射物发射点和本地前向轴，否则继续依赖 `body_height` 会造成表现位置不匹配。

### 3.5 关卡机关、出生点、据点、装饰物

- `LevelResource` 当前只有地块、路径、出生点、据点、波次等数组：`scripts/level/LevelResource.gd:27-63`。
- 出生点定义只有身份和格坐标：`scripts/path/SpawnPointDefinition.gd:6-13`；运行时固定圆柱：`scripts/path/PathManager.gd:126-156`。
- 据点定义只有身份和格坐标：`scripts/path/BasePointDefinition.gd:6-13`；运行时固定圆柱：`scripts/unit/BaseCore.gd:84-111`。
- 未发现 Decoration/Prop/Mechanism Definition、关卡序列化数组或运行时管理器。

所以“开放接口”不能只增加一个字段，必须先决定关卡内如何摆放、保存、加载和清理这些对象。

### 3.6 UI 图片与建筑选项卡面

已存在且已消费的 UI 图片字段：

- 建筑卡图：`BuildingDefinition.card_icon` → `BuildCardBar.gd:153-205`。
- 复制镜卡图：`CopyMirrorDefinition.card_icon` → `BuildCardBar.gd:138-143`。
- 敌人图：`EnemyDefinition.ui_icon` → `WaveTimelineModel.gd:31-48`。
- 地块详情图：`TileDefinition.ui_icon` → `TileInspectorPanel`。
- 资源图标：`EconomyPanel.resource_icon`。
- 时间按钮：`TimeControlPanel` 三个图标。
- 暂停菜单：`PauseMenu` 三个图标。
- 波次操作：`WaveControlPanel` 三个按钮图标和敌人回退图。
- 调试控制台/常驻层：面板背景及执行图标。

现有 `.tscn/.tres` 没有为上述字段配置任何非空 Texture2D，当前全部使用文字、字符或 StyleBox 回退。

建筑选项卡的边框、背景、选中态、禁用态仍由 `BuildCardBar.gd:241-265` 运行时硬编码 `StyleBoxFlat`；当前 `card_icon` 只能替换卡片中间图片，不能替换完整卡面。

## 5. 风险优先级

### P1

1. `TileDefinition.visual_scene`、`EnemyDefinition.visual_scene` 是断路接口，Inspector 看似可配但运行时无效。
2. 三类现役投射物没有模型接口；复制体没有与源建筑共享投射物模型配置。
3. 地块元素接入正式模型后，如果只改本体渲染，不同步快照路径，会造成真实物体与复制体美术不一致。
4. 关卡机关投射物、装饰物没有底层数据模型，无法通过单纯新增美术字段完成。

### P2

1. 建筑卡只开放图标，没有完整卡面背景/框体/状态图接口。
2. UI 美术接口零散，缺少统一 Theme/Art Definition；很多面板仍不可整体换皮。
3. 现有正式资源只有箭塔 1 级绑定世界模型，其余资源全部依赖灰盒。
4. 所有正式美术接口缺少非空资产自动测试。
5. 建筑错误根节点没有灰盒回退。

## 6. 进入方案设计前必须确认

1. **地块模型粒度**：地块基底要按格实例化 PackedScene，还是继续批量地形 Mesh，只开放材质/纹理集合？前者自由度高但节点数和 Draw Call 高；后者性能好但造型受约束。
2. **装饰物摆放方式**：按格/边吸附，还是允许关卡内自由 `Transform3D` 摆放？
3. **关卡机关投射物范围**：本次仅建立可供未来机关复用的通用投射物视觉配置，还是同时实现机关 Definition、摆放与发射逻辑？
4. **UI 范围**：“UI 图片接口”是否要求现役全部 HUD 可整体换皮，还是只要求现有按钮/图标槽位？
5. **建筑卡面范围**：只需要卡片主图，还是要开放背景、边框、选中、禁用、资源不足等完整状态图？
